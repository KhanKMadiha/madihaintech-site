Portfolio Assistant

A Claude-powered assistant that helps visitors explore my experience, projects and technical skills through conversation.

View GitHub (opens in a new tab)

The challenge and what I built

The challenge

A portfolio can show someone’s experience and projects, but visitors still have to find the information themselves. I wanted to make that easier by letting recruiters ask questions directly, while ensuring the answers remained accurate and trustworthy.

What I built

I built a Claude-powered Portfolio Assistant that answers questions about my experience and projects using a defined set of portfolio information, with secure API routing and clear boundaries around what it can answer.

How it works

Select a step to explore how the assistant answers a question.

Step 1 of 4

Ask a question

A visitor asks about my experience, technical skills or projects using the chat interface.

Step 2 of 4

Use portfolio context

The assistant receives a curated summary of my portfolio through its configured context, keeping responses focused on my documented experience.

Step 3 of 4

Generate an answer

Claude uses the question and available context to generate a concise response through the secure API integration.

Step 4 of 4

Respond or acknowledge limits

The assistant answers when it has the necessary information and acknowledges when something falls outside its knowledge rather than inventing details.

Evolution of the assistant

  1. IBM Watson

    Intents and entities

  3. Dialogflow CX

    Multi-turn routing

  5. Claude

    Grounded natural language

I started with Watson and Dialogflow CX, but maintaining predefined intents became increasingly restrictive as I explored more open-ended recruiter questions. Moving to Claude gave me a more flexible conversational experience, while introducing new considerations around grounding, security and scope.

Why I designed it this way

Three decisions shaped how I built the Portfolio Assistant.

  • Ground answers in portfolio information

    I wanted visitors to receive answers based on my actual experience and projects, rather than confident-sounding responses that might invent information.

  • Keep API credentials secure

    The Anthropic API credential belongs on the server side, not in a public browser. I used a Cloudflare Worker to separate the chat interface from the private API credential.

  • Know when not to answer

    I deliberately gave the assistant boundaries. If something isn’t included in its knowledge, it should acknowledge that rather than speculate about my experience or personal details.
